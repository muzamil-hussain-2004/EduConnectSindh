# Deployment Guide (free tier)

```
Browser ──► Vercel (React static files)
   │
   └──────► Render (Express API + Socket.IO + BullMQ worker)
                ├──► Neon     (PostgreSQL)
                └──► Upstash  (Redis: cache, rate data, job queue)
```

Vercel only serves the built React files. Every API call and the WebSocket go directly from the
browser to Render. Render talks to Neon (data) and Upstash (Redis).

## 1. Neon (database)

1. Create a project, copy the **connection string** (it ends with `?sslmode=require`).
2. From your PC, create the tables and the admin account in the cloud database:
   ```powershell
   cd backend
   $env:DATABASE_URL="<neon string>"; $env:ADMIN_EMAIL="you@example.com"; $env:ADMIN_PASSWORD="a-strong-password"
   npm run db:deploy
   npm run db:seed
   ```
   `db:deploy` applies migrations; `db:seed` adds Jamshoro areas, subjects and the admin.
   Never paste these values into a file that is committed.

## 2. Upstash (Redis)

Create a Redis database and copy the **`rediss://...`** URL (double `s` = TLS). Not the REST URL.

## 3. Render (API)

1. New → **Blueprint**, pick this GitHub repo. Render reads [render.yaml](../render.yaml).
2. Fill the prompted variables: `DATABASE_URL` (Neon), `REDIS_URL` (Upstash), `CLIENT_URL`
   (put a placeholder first, e.g. `https://example.com`).
3. After deploy, open `https://<name>.onrender.com/health` – it should answer `ok`.

Start command runs `prisma migrate deploy` each boot so the schema is always up to date.

## 3b. Hugging Face Space (API without a credit card)

Render's free tier may ask for a card. A Hugging Face Docker Space is a card-free alternative.

1. Create a free account at huggingface.co → **New → Space**. Name `educonnect-api`, SDK **Docker**
   (blank template), visibility **Public**.
2. Upload two files from [deploy/huggingface/](../deploy/huggingface) to the Space (Files → Add file):
   `Dockerfile` and `README.md`. The Dockerfile clones this GitHub repo, builds the backend,
   runs `prisma migrate deploy` and starts the API on port 7860.
3. Space → **Settings → Variables and secrets** → add **Secrets**: `DATABASE_URL`, `REDIS_URL`,
   `CLIENT_URL`, `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET` (and optionally `AI_API_KEY`,
   `AI_BASE_URL`, `AI_MODEL`). `NODE_ENV`, `PORT` and `COOKIE_SAME_SITE` are already set in the image.
4. The Space builds automatically (about 5 minutes). Your API URL is
   `https://<username>-educonnect-api.hf.space`; check `/health`.
5. Use that URL in Vercel (`VITE_API_URL=<url>/api/v1`, `VITE_SOCKET_URL=<url>`).
6. To deploy new code: push to GitHub, then Space → Settings → **Factory rebuild**.

## 4. Vercel (frontend)

1. Add New Project → import the repo → **Root Directory: `frontend`**.
2. Environment variables:
   - `VITE_API_URL` = `https://<name>.onrender.com/api/v1`
   - `VITE_SOCKET_URL` = `https://<name>.onrender.com`
3. Deploy. [vercel.json](../frontend/vercel.json) rewrites all paths to `index.html` so refreshing
   on `/dashboard` works (React Router handles routing in the browser).

## 5. Connect them

Back in Render, set `CLIENT_URL` to the exact Vercel URL (no trailing slash) and redeploy.
This sets CORS and Socket.IO to allow only your frontend.

## Why these settings?

- **`COOKIE_SAME_SITE=none`**: `vercel.app` and `onrender.com` are different sites. The refresh
  token cookie is only sent cross-site when it is `SameSite=None; Secure`. Locally the Vite proxy
  makes everything same-origin, so `lax` is enough there.
- **`trust proxy`**: Render sits behind a proxy; Express needs it to see HTTPS and real IPs.
- **Secrets** are generated by Render (`generateValue`) and never live in Git.

## Free-tier limits

- Render sleeps after ~15 min idle; the first request takes ~30–60 s. Ping `/health` with
  UptimeRobot every 10 min before a demo.
- Uploaded verification documents are stored on Render's disk, which is wiped on redeploy. Fine for
  a demo; production would use object storage (S3/R2).
- Upstash has a daily command quota; BullMQ polling uses some of it.
- Delete the local demo accounts and use a strong admin password.

## Troubleshooting

| Symptom               | Cause                                                    |
| --------------------- | -------------------------------------------------------- |
| CORS error in browser | `CLIENT_URL` differs from the Vercel URL                 |
| Logged out on refresh | `COOKIE_SAME_SITE` not `none`, or API URL not HTTPS      |
| 404 on page refresh   | `vercel.json` missing / root directory not `frontend`    |
| API crashes on boot   | Missing/invalid `DATABASE_URL` or `REDIS_URL` (see Logs) |
